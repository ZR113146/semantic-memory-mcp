# ADR: new adr_list MCP tool for structured, human-browsable decision index

## Summary

New adr_list MCP tool: human-browsable, filterable ADR index — the MEMORY.md equivalent for architectural decisions

## Content

**决策**：新增 adr_list MCP tool 作为 ADR 的人类可浏览索引（MEMORY.md 等价物）。返回结构化 JSON 列表，支持 project/kind/status/entity_key 过滤和 limit 控制。

**背景**：ADR 记忆以 memory_item 行形式存储，唯一检索方式是 memories_retrieve 的 FTS/向量语义查询——没有类似 MEMORY.md 的"目录"视图。用户无法回答"这个项目有哪些活着的决策"而不依赖语义碰运气。adr_list 提供一个零查询词的轮廓概览。

**API**：
```
adr_list {project, kind?, status?, entity_key?, limit?}
→ {project, total, items: [{id, kind, layer, title, summary, entity_key, status,
    importance, confidence, reusability, specificity, hit_count, decay,
    version, supersedes, created_at, updated_at}]}
```

**SQL**：SELECT 17 列 + 参数化过滤（scope_project + 可选 kind/status/entity_key）+ ORDER BY 复合得分 DESC + LIMIT

**否决的替代**：
- 纯前端 Graph UI 显示：需要启动 HTTP server + 浏览器，不适用于 MCP-only 会话
- 扩展 memories_retrieve 加 layer 过滤：改 cbm_memory_query_t 结构体的波及面太大（10+ 调用方），且语义查询和目录查询是正交需求

**锚点**：store.c ~L4943-5040（cbm_store_memory_adr_list）、mcp.c ~L4478-4534（handle_adr_list）、2026-07-07 commit
