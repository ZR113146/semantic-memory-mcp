# ADR Markdown mirror V1 keeps SQLite authoritative

## Summary

V1 adds a deterministic project-local ADR Markdown projection for Git review while SQLite remains the only writable authority and global/import support stays out of scope.

## Content

[Decision] ADR Markdown mirror V1 keeps each project SQLite memory database as the sole write authority. A new adr_export tool provides plan, write, and check modes and writes a deterministic generated mirror under <repo>/.semantic-memory/adr. The default ADR set is exactly project-scoped non-deleted decision and constraint items across all lifecycle statuses. Global memory is not unioned or duplicated into project repositories in V1. Markdown files are generated projections and cannot be imported or treated as a second authority.

[Context] SQLite is required for lifecycle state, relations, scoring, transactions, retrieval, and indexing, but binary database changes are not reviewable as useful Git diffs. Legacy ADR alignment is complete, so the next safe step is a one-way textual mirror. Existing adr_list is capped and omits content and about_code anchors, while resolve_memory_store already provides query-only handles and the artifact pipeline demonstrates Windows-safe atomic replacement.

[Rejected alternatives] Do not replace SQLite with Markdown; do not allow bidirectional editing in V1; do not generate superseding ADRs for syntax-only differences; do not export hit_count, decay, confidence, reusability, specificity, or updated_at because runtime churn would pollute Git history; do not duplicate global ADRs into every project repository; do not normalize or rewrite stored content during projection.
