# ADR: version auto-increments on supersede — old_version + 1

## Summary

ADR version increment: when supersedes is set, new item version = old_version + 1, giving supersedes chains a naturally ascending sequence

## Content

**决策**：supersedes 字段触发写入时，查询被取代条目的 version，新条目 version = old_version + 1。若旧条目未找到（已删除/不同 scope），version 保持默认 1。

**背景**：截至 2026-07-07，所有决策的 version 永远 = 1——supersedes 链上 2-3 条条目全为 version=1，无法从字段上区分演进顺序。git 交叉核对显示 semantic-memory-mcp 有 4 条 supersedes 链、zhiwei-kb-system 有 9 条链，都没有版本递增。

**落地**：handle_events 中在设 item.version=1 之后，若 supersedes 非空，用一条 SELECT version FROM memory_item WHERE id=?1 查询旧条目版本，取 sqlite3_column_int(0)+1。查询在同一事务内，在 cbm_store_memory_append_candidate INSERT 之前执行，所以旧条目的 version 还存活着。

**否决的替代**：
- 用 status transition 模拟版本（active→archived→active）：不可靠，且不能表达"同一条目三个版本"
- 在 store 层做 version 递增：需要改 cbm_store_memory_append_candidate 的签名，破坏 API

**锚点**：mcp.c ~L5151-5167（version increment）、2026-07-07 commit
