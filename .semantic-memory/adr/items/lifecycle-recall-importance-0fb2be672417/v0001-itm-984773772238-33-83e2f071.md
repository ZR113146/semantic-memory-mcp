# memory.event

## Summary

召回为什么只取 supersede 链最新一环、证伪为什么必须下调 importance

## Content

【决策】两件生命周期修正:(1) 显式 supersedes 写入时 archive 被取代的旧项(移出召回主线,与 merge 路径一致),旧版本留盘作历史;(2) memory_feedback 的 wrong/stale 同时下调 importance(wrong -0.5+retract,stale -0.2+archive)。
【背景】(1) 召回排序里 ADR 不可变且会累积版本,recall 应只取 supersede 链最新一环;但 P3-d 的显式 supersedes 原来不 archive 旧项,导致新旧两版都召回。(2) 召回排序 = importance+confidence+reusability+specificity+hit_count-decay,importance 是独立正项;证伪只降 confidence/decay 而不动 importance,会让一条被推翻的高 importance 决策靠虚高的 0.9 继续赖在召回前列(僵尸)。
【背景补充】捡回被放弃的分支 = 写一条新 ADR supersede 旧的,而非复活旧分数——把价值的非单调摆动转化为 supersede 链的单调增长。
【落地锚点】handle_events 显式 supersede 时 archive 旧项 + memory_feedback 下调 importance;提交 27d992c。
