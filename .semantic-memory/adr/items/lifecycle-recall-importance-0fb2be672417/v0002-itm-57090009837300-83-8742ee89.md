# 召回为什么只取 supersede 链最新一环、证伪(feedback wrong/stale)为什么必须同时下调 importance

## Summary

召回为什么只取 supersede 链最新一环、证伪(feedback wrong/stale)为什么必须同时下调 importance

## Content

[Decision] 两件生命周期修正：(1) 显式 supersedes 写入时 archive 被取代的旧项(移出召回主线，与 merge 路径一致)，旧版本留盘作历史；(2) memory_feedback 的 wrong/stale 同时下调 importance(wrong −0.5+retract，stale −0.2+archive)。

[Context] (1) 召回排序里 ADR 不可变且会累积版本，recall 应只取 supersede 链最新一环；但 P3-d 的显式 supersedes 原来不 archive 旧项，导致新旧两版都召回。(2) 召回排序 = importance+confidence+reusability+specificity+hit_count−decay，importance 是独立正项；证伪若只降 confidence/decay 而不动 importance，会让一条被推翻的高 importance 决策靠虚高的 0.9 继续赖在召回前列(僵尸)。原则补充：捡回被放弃的分支 = 写一条新 ADR supersede 旧的、而非复活旧分数——把价值的非单调摆动转化为 supersede 链的单调增长。

[Rejected alternatives] (a) 显式 supersede 时不 archive 旧项(P3-d 原行为)——新旧两版同时召回，违背"只取最新一环"。(b) 证伪只降 confidence/decay、不动 importance——高 importance 被推翻项靠虚高分继续霸榜(僵尸)。

[Anchors] handle_events 显式 supersede 时 archive 旧项(src/mcp/mcp.c)；memory_feedback 的 wrong/stale 下调 importance——核心在 cbm_store_memory_feedback(src/memory/memory_store.c，原 store.c 经 38f8d25 抽离)。提交 27d992c(2026-06-30，"P4 recall=latest-link + importance falsification"，改 src/mcp/mcp.c + src/store/store.c + tests/test_memory.c)。测试 memory_feedback_wrong_retracts_from_default_retrieval 佐证。
