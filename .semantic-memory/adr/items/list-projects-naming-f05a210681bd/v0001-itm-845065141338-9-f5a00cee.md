# memory.event

## Summary

list_projects 怎么定项目名才能和 scope_project 一致、不造幻影项目

## Content

【决策】list_projects 的项目名以数据为权威——打开每个库读 memory_item.scope_project 作为 canonical 名,graph 库和它的 -memory.db sidecar 按 canonical 名去重合并成一条,带 has_memory 标志。
【背景】db-split 后 list_projects 用文件名反推项目名,只砍 .db 不识别 -memory 后缀,把 sidecar 列成幻影项目 "<project>-memory"。这个幻影名与库里存的 scope_project 不匹配,导致 memories_retrieve 召回 0;且项目名本身含 -memory 时(如 D-semantic-memory-mcp)纯靠文件名无法消歧。
【否决的替代】在 is_project_db_file 直接排除 -memory.db——实测会让纯 memory 项目(只有 sidecar、无 graph 库)的唯一数据文件消失,list_projects 返回空。这个方案被构建后实测推翻。
【落地锚点】canonical_project_name(读 scope_project)+ handle_list_projects(去重合并);提交 d25f939。
