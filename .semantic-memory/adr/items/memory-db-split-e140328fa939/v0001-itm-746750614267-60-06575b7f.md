# memory.event

## Summary

为什么 semantic-memory-mcp 的长期记忆要永久独立于代码图谱的 .db 文件(含 option C 选型依据)

## Content

【决策】长期记忆永久存放在独立的 <project>-memory.db 文件,与代码图谱 <project>.db 物理分离(起源会话里编号为 option C / per-project files)。物理解耦不可回退;语义关联只通过 about_code 锚边表达。
【背景】reindex(cbm_unlink 删 graph .db)和 install/update/uninstall(cbm_remove_indexes 扫缓存删可重建索引)两条路径都只删 graph .db,记忆独立成文件后不被波及(install 靠 -memory.db 后缀排除)。塞回 <project>.db 会精确重触删库 bug。
【否决的替代】起源会话评估了多个方案,选 option C(每项目独立文件)。关键技术约束决定了为什么是 C:store_authorizer 硬性阻止 ATTACH(防 SQL 注入建文件),所以记忆库无法通过 ATTACH 跨库 join 图谱。因此 anchor-boost 不用 ATTACH,改为由 MCP handler 传入 borrowed graph handle(cbm_memory_query_t.graph_db),仅在给 code_context 时设置,NULL 则静默跳过 boost、记忆照常返回。一次性迁移 cbm_store_migrate_memory_from_graph 用 throwaway authorizer-free sqlite3 句柄 + 参数绑定路径(非 file: URI,因 Windows 盘符+反斜杠破坏 URI)把旧合库的 memory_* 行搬出。
【落地锚点】cbm_memory_db_path(路径)、resolve_memory_store(独立开库 create-if-absent)、memory_apply_anchor_boost(borrowed handle 不用 ATTACH);提交 e4c4b7f + ad43fb4。本条经跨窗口校核(起源会话 0e81bc89)补全了 option C 选型依据,supersede 初版。
