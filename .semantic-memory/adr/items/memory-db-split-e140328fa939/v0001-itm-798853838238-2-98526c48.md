# memory.event

## Summary

为什么 semantic-memory-mcp 的长期记忆要永久独立于代码图谱的 .db 文件

## Content

【决策】长期记忆永久存放在独立的 <project>-memory.db 文件,与代码图谱的 <project>.db 物理分离。这个物理解耦不可回退;语义关联只通过 about_code 锚边表达,可以加强,但两个库的文件永远分开。
【背景】reindex 用 cbm_unlink 删 graph .db 重建图谱,install/update/uninstall 的 cbm_remove_indexes 扫缓存删可重建索引——两条路径都只删 graph .db。记忆独立成文件后,这两条删除路径都不碰它(install 路径靠 -memory.db 后缀排除)。若把记忆塞回 <project>.db,reindex 和 install 会精确重新触发删库 bug。
【否决的替代】(a) 记忆与图谱共用 <project>.db——这正是 e4c4b7f 之前的状态,每次 index_repository 都连记忆一起删;(b) 完全弃用 MCP 记忆只靠平台 .md 文件——失去 UserPromptSubmit 自动召回这唯一通道。
【落地锚点】cbm_memory_db_path 派生 <project>-memory.db 路径;resolve_memory_store 独立打开记忆库(create-if-absent,不依赖图谱是否索引过)。提交 e4c4b7f(物理分离)+ ad43fb4(堵住 install 删记忆的第二条路径)。
