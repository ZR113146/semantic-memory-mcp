# 定调：记忆库引入 global 作用域库，承载一切项目间高复用信息（不止画像）

## Summary

缺口 B 定调：记忆库从 project 单维切分升级为按作用域分层(project/global)，新增 global 库存放 scope_project=NULL 的高复用信息(画像/偏好/跨项目经验)，检索时项目库+global 库 union；范围不限画像，凡项目间可高度复用者皆可写入 global 口子。

## Content

【定调】缺口 B 的收口方向已确定，且范围扩大：不止用户画像，凡"项目间可高度复用"的信息(用户画像/偏好、跨项目通用经验/约定/参考)都应有一个 user/global 作用域的口子可写可读。即记忆库要从"project 单维物理切分"升级为"按作用域分层(project / global)"。

【目标态】新增 global 作用域库 <cache>/__global__-memory.db(或等价命名)，scope_project=NULL 的记忆落此。所有项目检索时，除打开本项目 <project>-memory.db 外，额外 union 打开 global 库 —— 于是高复用信息一次写入、各项目皆可见。

【已定方向 A 的改动面】1) cbm_memory_db_path(store.c:1250)增加 global 路由(scope_project 为空 → global 库路径)；2) resolve_memory_store(mcp.c:4457)支持同时持有项目库+global 库句柄并 union 检索(现仅开单库、切项目即关旧句柄)；3) 写入侧：高复用记忆正确置 scope_project=NULL，使其路由进 global 库(否则即便有 global 库也进不去——本次画像就是 scope_project 有值/scope_user 空才误落项目库)；4) reindex/install 的删库逻辑(cli.c:2655 MEM_SUFFIX)与 phantom-name guard(mcp.c:4413)需把 global 库一并纳入"持久、不可重建、排除删除"的保护。

【约束】沿用 memory-db-split 既有不变量：global 库同样不能被 reindex/install 清掉；store_authorizer 仍禁 ATTACH，跨库 union 走"分别开句柄、应用层合并"而非 SQL ATTACH(与 anchor-boost 用 borrowed handle 同思路)。
