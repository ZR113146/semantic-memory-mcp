# memory.event

## Summary

confidence/reusability 怎么由代码图谱信号算而不是靠申报的 0.5 默认分

## Content

【决策】写入带 about_code 锚的记忆时,confidence/reusability 由锚符号的图谱拓扑算(入度→confidence,出度+是否入口点+锚数→reusability),不盲信申报值。申报值语义:等于默认 0.5 视为"未设",直接取图谱信号;非 0.5 视为相对 0.5 的偏移(写入者看到图谱看不到的前瞻价值),叠加到信号上。无锚或无图谱则保留申报值(L3 回退)。
【背景】其他窗口 AI 写记忆时打分全默认 0.5,使衰减模型(conf·reuse 驱动)退化成纯时间一刀切,真 ADR 和废笔记同速衰减。三层评分管线:L1 图谱客观计算 > L2 类型先验 > L3 申报附依据。架构定信号源,数值权重设为可配置常量靠真实数据迭代。
【否决的替代】(a) 二元硬开关(有锚=不衰减/无锚=可衰减)——多余且是退步,ADR 不可变性应作为高 reusability 的涌现属性,不需独立标志位;(b) 纯人工申报——必然回落 0.5 中位数。
【落地锚点】cbm_store_memory_score_from_anchors(图谱信号)+ memory_l1_blend(申报偏移合成);提交 b67142b。同提交修复了 about_code 锚的 use-after-free——该锚自存在以来一直是空操作(adoc 提前释放),整个语义锚定层此前休眠。
