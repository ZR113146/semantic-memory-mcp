# confidence/reusability 为什么由 about_code 锚的代码图谱拓扑算出，而不是盲信申报的 0.5 默认分

## Summary

confidence/reusability 为什么由 about_code 锚的代码图谱拓扑算出，而不是盲信申报的 0.5 默认分

## Content

[Decision] 写入带 about_code 锚的 decision/constraint 记忆时，confidence/reusability 由锚符号的代码图谱拓扑算出，不盲信申报值：入度→confidence（0.5 + 0.04·max_in，上限 0.95），出度+入口点+锚数→reusability（0.4 + 0.02·max_out + 0.05·(锚数−1)，命中入口点再 +0.3，上限 1.0）。申报值语义：等于默认 0.5 视为"未设"→直接取图谱信号；非 0.5 视为相对 0.5 的偏移叠加到信号上。无锚或无图谱则保留申报值。

[Context] 其他窗口 AI 写记忆时打分全默认 0.5，使 decay 模型（conf·reuse 驱动）退化成纯时间一刀切，真 ADR 与废笔记同速衰减。【核实更正】实际落地是 L1（图谱信号）与 L3（申报值）两路融合——代码里并无独立的 L2「类型先验」层（旧记忆"三层评分管线"表述与代码不符，据 memory_l1_blend 实现更正为两路）。同提交还修复了 about_code 锚的 use-after-free（adoc 在读取锚之前被释放，使锚一直是空操作），该 UAF 之前让整个语义锚定层休眠。

[Rejected alternatives] (a) 二元硬开关（有锚=不衰减/无锚=可衰减）——多余且是退步，ADR 不可变性应作为高 reusability 的涌现属性，不需独立标志位；(b) 纯人工申报——必然回落 0.5 中位数。
