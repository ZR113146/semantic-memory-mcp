[Decision] confidence/reusability 由统一的三层优先级函数 cbm_memory_score_item（memory_store.c，一处可读可测）合成：L1 图谱信号（有 about_code 锚且锚符号在图谱中解析时——入度→conf 0.5+0.04·max_in 上限0.95；出度+入口点+锚数→reuse）＞ L2 类型先验（按 kind 的 reuse 基线：decision/constraint 0.7、preference 0.75、reference 0.6、lesson 0.55、fact 0.5、event 0.4、未知 0.5）＞ L3 申报值（0.5=未设→取上层基准；非 0.5→相对 0.5 的偏移叠加）。合成单调（max）：每层只能抬高基准、绝不把有锚低度数记忆压到其类型先验之下。confidence 不设类型先验（kind≠真伪），只由 L1+L3 决定。

[Context] 【核实更正 v2→v3】L1>L2>L3 是项目构型时的设计意图（L2 用于显式区分"有锚代码记忆"与"无锚 user 类记忆"），后期追加 L2 时放在混合函数之外，早期代码由其他窗口 AI 写、未细核。核实 git：原始提交 b67142b（2026-06-30，早于外部 AI 改动）只描述 L1+L3 两路，L2 当时散落为 layer 默认 + P4 reuse 下限。我的 v2 据此误判"代码无 L2"，抹掉了真实设计意图。本次把三层收拢进单一 cbm_memory_score_item，L2 从散落统一为 kind 先验表，使设计=实现、可溯源；并修掉"有锚低度数 ADR（reuse 0.4）被无锚（0.7）顶掉、被衰减熬走"的反常。定位：加结构+修反常，非调参（打分对召回的实际增益仍待真实数据验证）。
