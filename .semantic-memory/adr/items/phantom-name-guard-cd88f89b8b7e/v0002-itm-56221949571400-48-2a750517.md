# 怎么防止幻影项目名造成 -memory-memory.db 孤儿库、且不误伤真名含 memory 的项目

## Summary

怎么防止幻影项目名造成 -memory-memory.db 孤儿库、且不误伤真名含 memory 的项目

## Content

[Decision] resolve_memory_store 和 handle_events/handle_memories_retrieve 入口用 normalize_phantom_project 归一化项目名：若传入名以 -memory 结尾、且去掉后缀后存在 <base>-memory.db，判定为幻影名，归一化到真名 <base>；真名本身以 -memory 结尾的(如 D-semantic-memory-mcp，去后缀得 D-semantic-memory-，无对应库)不误伤。

[Context] 旧 list_projects 吐出的幻影名 <project>-memory 被传回写入/检索时，cbm_memory_db_path 会再拼一个 -memory.db 造出 <project>-memory-memory.db 孤儿库，且 SQL 过滤 scope_project 也对不上。归一化在开库和 SQL 过滤前统一做，两者用同一真名。

[Rejected alternatives] 不归一化、任由幻影名传回——正是所修 bug：拼出 <project>-memory-memory.db 孤儿库、scope_project 过滤失配、召回 0。只在开库侧或只在 SQL 侧单点归一化也不够，必须两处用同一真名。

[Anchors] normalize_phantom_project(核心归一化)，在 handle_events + handle_memories_retrieve 入口调用；cbm_memory_db_path(被误拼的路径来源，现 src/memory/memory_store.c)；提交 d25f939。
