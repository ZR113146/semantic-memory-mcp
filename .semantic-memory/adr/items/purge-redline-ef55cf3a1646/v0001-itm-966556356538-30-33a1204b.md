# memory.event

## Summary

为什么带代码锚的决策 ADR 永远不能被物理删除只能归档

## Content

【决策】retention sweep 的物理 purge 必须排除带 about_code 锚的 decision/constraint/lesson ADR。这类 ADR 即便被 soft-delete 且过了 grace window,也只停留在 soft-deleted(隐藏)状态,永不物理删除。物理 purge 只作用于无锚的纯笔记。
【背景】带锚决策 ADR 是 supersede 链的链头。一条记录"为什么放弃方案 B"的 ADR,在未来重新捡起 B 时信息价值最高(它存着否决理由)。若被 sweep 物理清除,supersede 链断头,捡回分支时读不到当初的否决理由。所以决策 ADR 只能 archive(沉出召回主线),永不 purge。
【否决的替代】无差别 purge 所有过期 soft-deleted 项——会丢失带锚决策的历史链头。
【落地锚点】cbm_store_memory_purge_expired 的 SELECT 加红线条件(NOT (kind in decision/constraint/lesson AND EXISTS about_code edge));提交 ba0657c。测试 memory_purge_spares_anchored_decision_adr。
