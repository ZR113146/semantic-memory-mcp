# 为什么带 about_code 锚的 decision/constraint/lesson ADR 永不物理 purge、只能停留归档态

## Summary

为什么带 about_code 锚的 decision/constraint/lesson ADR 永不物理 purge、只能停留归档态

## Content

[Decision] retention sweep 的物理 purge 必须排除带 about_code 锚的 decision/constraint/lesson ADR。这类 ADR 即便被 soft-delete 且过了 grace window，也只停留在 soft-deleted(隐藏)状态，永不物理删除。物理 purge 只作用于无锚的纯笔记。

[Context] 带锚决策 ADR 是 supersede 链的链头。一条记录"为什么放弃方案 B"的 ADR，在未来重新捡起 B 时信息价值最高(它存着否决理由)。若被 sweep 物理清除，supersede 链断头，捡回分支时读不到当初的否决理由。所以决策 ADR 只能 archive(沉出召回主线)，永不 purge。红线落在 retention-sweep 的 purge SELECT 上：cbm_store_memory_purge_expired 的候选 SELECT 加条件 NOT (kind in decision/constraint/lesson AND EXISTS about_code edge)；手动删除路径 cbm_store_memory_delete 的 purge 模式(is_purge 分支)是同族的直接物理删除入口，同受此不变量约束。

[Rejected alternatives] 无差别 purge 所有过期 soft-deleted 项——会丢失带锚决策的历史链头，捡回分支时读不到否决理由。
