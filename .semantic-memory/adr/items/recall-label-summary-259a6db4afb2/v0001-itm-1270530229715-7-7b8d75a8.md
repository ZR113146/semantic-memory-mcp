# Untitled ADR

## Summary

召回 hook 为什么改成优先显示 summary、写入侧为什么不再给 title 塞 memory.event 默认值

## Content

【决策】召回标签优先用 summary 而非 title,且写入侧不再给 title 塞 "memory.event" 默认值。读写两处一起改。
【背景】自动召回 hook(UserPromptSubmit 每轮注入,是 MCP 记忆相对 .md 唯一不可替代的投递通道)对几乎每条记忆都显示 "memory.event" 作标签——核实:D-semantic-memory-mcp 16 条里 13 条、D-zhiwei-kb-system 8/8、global 5/5 的 title 字段字面就是 "memory.event"。根因双因:(写)handle_events 里 item.title 缺省 = title ? title : (type ? type : "memory.event"),写入方不传 title 就被毒化(注意 event.type 默认 memory.event 是另一个字段,该保留);(读)hr_memory_label 先取 title 后取 summary,毒化的 title 非空就把有信息量的 summary 永远挡掉。后果:每轮召回注入是一串相同的无信息标签,agent 无法分辨任何一条,核心功能在展示层被废。与当年 all-0.5 塌缩同构——默认值毒化 + 读取侧优先级放大。
【否决的替代】只改写入侧:救不了存量(29 条已存的 title 字面就是 "memory.event" 字符串);必须靠读取侧改"优先 summary"才能零迁移救活存量。在 hr_memory_label 里硬编码跳过 "memory.event" 字面量:hacky,且不如"summary 本就是 schema 设计的 query-like 结论字段、最适合当标签"这一正解干净。
【落地锚点】hr_memory_label(hook_recall.c):顺序改为 summary→title→content;handle_events(mcp.c):item.title = title(无则 NULL,显示侧自然回退 summary)。e2e 验证:从 D-zhiwei-kb-system 召回 5 条全显示真 summary(4 global+1 项目 decision)。提交 233705b,已部署生产并核实。
