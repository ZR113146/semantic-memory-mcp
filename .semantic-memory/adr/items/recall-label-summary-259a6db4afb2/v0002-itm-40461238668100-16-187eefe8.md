# 召回 hook 为什么改成优先显示 summary、写入侧为什么不再给 title 塞 memory.event 默认值

## Summary

召回 hook 为什么改成优先显示 summary、写入侧为什么不再给 title 塞 memory.event 默认值

## Content

[Decision] 自动召回标签优先用 summary 而非 title；写入侧不再给 title 塞 "memory.event" 默认值。读、写两处一起改。

[Context] 自动召回 hook（UserPromptSubmit 每轮注入，是 MCP 记忆相对文件版 .md 唯一不可替代的投递通道）此前对几乎每条记忆都显示 "memory.event" 作标签。双因：(写) handle_events 里 item.title 缺省 = title?title:(type?type:"memory.event") 被毒化；(读) hr_memory_label 先取 title 后取 summary，毒化的非空 title 永远挡掉有信息量的 summary。后果：每轮召回是一串相同无信息标签，agent 无法分辨任何一条，核心功能在展示层被废。与 all-0.5 打分塌缩同构——默认值毒化 + 读取侧优先级放大。

[Rejected alternatives] 只改写入侧：救不了存量（当时 29 条已存 title 字面就是 "memory.event"），必须靠读取侧改"优先 summary"才能零迁移救活存量。在 hr_memory_label 里硬编码跳过 "memory.event" 字面量：hacky，不如"summary 本就是 schema 设计的 query-like 结论字段、最适合当标签"这一正解干净。

[Anchors] 提交 233705b（fix(memory): recall hook shows summary, not the useless 'memory.event' title，2026-07-01）。hr_memory_label(src/cli/hook_recall.c) 顺序改为 summary→title→content；handle_events(src/mcp/mcp.c) 改为 item.title=title（无则 NULL，显示侧自然回退 summary）。这两个文件未受 store→memory_store 抽离影响，路径仍有效。
