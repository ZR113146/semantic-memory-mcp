# 召回评测崩到 match 0.26 的真根因是评测 seed 被格式门拒(非召回退化)；修法=FTS overlap 区间打分+glo

## Summary

召回评测崩到 match 0.26 的真根因是评测 seed 被格式门拒(非召回退化)；修法=FTS overlap 区间打分+global 降权+评测修复

## Content

[Decision] 三件一起改，收口"召回评测崩到 match 0.26"的调查。(A) FTS 命中的 retrieval_score 从扁平 1.0 改为按 query 归一化的 token overlap(取 title/summary/content 三者 max)，再区间映射到 [0.5,1.0]；(B) 项目查询中 global(scope_project=NULL)记忆的 retrieval_score 乘 MEMORY_GLOBAL_SCOPE_WEIGHT=0.5 降权，并加 CBM_MEMORY_NO_GLOBAL_UNION env 开关可完全跳过 union；(测试侧) 评测 seed 补独立 summary、seed 被 policy 拒即大声报错、强制隔离 global 使评测确定性。

[Context] 真根因：调查发现 match=0.26/top1=0.13 根本不是召回退化——评测 seed 对 decision/constraint/lesson 没写 summary，被格式门(missing_summary / summary==content)拒收，9 条里 6 条从未入库，召回当然找不到。0.826 老基线是格式门加入之前测的，门加入后评测静默失效至今无人重跑。补 summary 后 match 立即跳回 1.0 → 召回从来没坏(用户直觉全程正确)。为什么 A 用区间映射而非裸 overlap：FTS overlap(0-1) 和向量 cosine(~0.1-0.4) 量纲不同不能直接混排；裸 overlap 会让"只共享停用词"的词面命中掉到强语义向量命中之下，直接测挂 memory_embedding_ranks_semantic_neighbor_higher。映射到 [0.5,1.0]：任何词面 FTS 命中仍压过纯向量猜测，FTS 命中之间仍按 overlap 排序——同时修了"画像偶然 bigram 命中霸榜"和过了语义单测。

[Rejected alternatives] (a) 裸 overlap 当分——测挂语义单测。(b) 只改测试 seed 不改 FTS 打分——扁平 1.0 的"偶然命中=完整命中"是生产侧 CJK 真缺陷(长记忆易偶然命中霸榜)，不能只补测试。(c) 靠 global union 污染解释评测低分——干净对照(隔离 global 数字不变)已证伪、撤回。

[Anchors] FTS 打分 retrieval_score=0.5+0.5·overlap，复用 memory_token_overlap，落在 cbm_store_memory_retrieve(src/memory/memory_store.c)；union 段 global 降权 MEMORY_GLOBAL_SCOPE_WEIGHT + CBM_MEMORY_NO_GLOBAL_UNION 在 handle_memories_retrieve(src/mcp/mcp.c)；scripts/memory_recall_cases.py 补 summary、memory_recall_eval.py 加 seed 校验+隔离。提交 5cfa50c(2026-07-01)。38f8d25 抽离后 FTS 打分/overlap 现居 src/memory/memory_store.c。验证：eval match 1.0/top1 0.739/mrr 0.846 重建基线通过；真实项目查询 bullseye。
