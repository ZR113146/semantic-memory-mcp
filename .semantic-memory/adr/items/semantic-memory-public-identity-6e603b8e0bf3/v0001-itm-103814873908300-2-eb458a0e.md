# semantic-memory-mcp 重命名后，对外 recall 标签、hook shim、MCP serverInfo 和更新地址应如何保持一致？

## Summary

semantic-memory-mcp 重命名后，对外 recall 标签、hook shim、MCP serverInfo 和更新地址应如何保持一致？

## Content

[Decision]
所有新产生的公开身份统一使用 semantic-memory-mcp：召回与图谱增强标签为 [semantic-memory-mcp]，Claude recall shim 为 semantic-memory-recall，MCP serverInfo.name、后台更新地址、UI fallback 和生成产物署名均使用 semantic-memory-mcp。安装升级仍识别并清理旧 cbm-memory-recall，但不重命名内部 cbm_ C 符号或历史兼容缓存。

[Context]
2026-07-10。项目已在 2026-06-26 完成品牌重命名，但后续新增 recall hook 继续硬编码旧标签，且一次 upstream 合并恢复了 MCP serverInfo 与更新地址中的旧品牌。Claude 验收因此把正确的 semantic-memory-mcp 二进制误读成旧系统。

[Rejected alternatives]
1. 保留旧标签作为协议稳定名：拒绝，因为它直接误导双平台验收且没有代码注释声明为兼容协议。
2. 全量重命名内部 cbm_ 符号和历史缓存目录：拒绝，风险与收益不成比例，且会扩大迁移面。
3. 同时输出新旧两个标签：拒绝，会污染上下文并让自动验收产生歧义。
