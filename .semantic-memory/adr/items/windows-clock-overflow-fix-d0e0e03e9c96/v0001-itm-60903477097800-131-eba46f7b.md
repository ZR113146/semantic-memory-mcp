# Windows cbm_now_ns 为什么改用溢出安全的整/余秒分离算法（QPC count·1e9 会溢出 uint64）

## Summary

Windows cbm_now_ns 为什么改用溢出安全的整/余秒分离算法（QPC count·1e9 会溢出 uint64）

## Content

[Decision] Windows 版 cbm_now_ns 改用溢出安全算法：(q/f)*1000000000 + (q%f)*1000000000/f（q=QPC count，f=freq），替代原来的 count.QuadPart*1000000000/freq。

[Context] 原式先算 count·1e9 再除 freq。count 是 QPC 自开机的计数，开机超过约 30 分钟(10MHz 计时器)后 count·1e9 溢出 uint64、回绕成小而非单调、约 30 分钟一周期的值。该值是 memory_make_id 的时间成分，回绕导致 id 重复 → memory_event 主键冲突 → "failed to append memory event" 在长开机进程上可靠复现。这正是 [[memory-id-uniqueness]](96a5a21 改用 cbm_now_ns 以求唯一)在 Windows 上被击穿的底座缺陷：id 方案没错，时钟源溢出了。POSIX 路径(tv_sec·1e9+tv_nsec)不受影响。

[Rejected alternatives] (a) 保留原式——溢出仍在。(b) 回退用 memory_now_ms(秒精度)——破坏唯一性(同秒撞)、且它本就依赖 cbm_now_ns。(c) 重启进程/机器规避——只是把溢出时钟推回起点，30 分钟后复发，非修复。

[Anchors] 提交 446c8cf(fix(memory): repair dead write path + consolidate scoring，2026-07-08)，src/foundation/platform.c 的 cbm_now_ns(Windows 分支)。时间成分消费者 memory_make_id 现居 src/memory/memory_store.c。排错手册见 [[failed-to-append-three-root-causes]]。
