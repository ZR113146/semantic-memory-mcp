# memory.event

## Summary

写入门的锚定/结构/引用维为什么是建议而不是强制拒绝

## Content

【决策】写入门的三个维度(锚定/结构/引用)以 advice 形式提示,绝不拒绝写入。响应字段:anchored(bool)、anchoring_advice(无锚 decision 类)、structure_advice(缺 ADR 四段结构)。结构检测故意宽松(中英关键词、不要求格式、>=80字才查),只在缺"否决的替代"等要素时轻提示。
【背景】format gate 原来只防畸形(非空/不双编码/summary≠content)。长出三维但定调为 helper 而非 gatekeeper——因为纯 memory 项目必须可写(自动召回 hook 是它唯一不可替代的投递通道),硬拒会砸掉这个通道和存量记忆。
【否决的替代】硬强制 about_code(decision 无锚就拒绝)——会让纯 memory 项目无法写入,违背"纯 memory 被容忍、可见、非特权"的定性。
